1. 무엇을 고쳤나요?

The Hacker News — 금지와 조회 실패를 구분하고 대체 경로 추가

기존 설정은 The Hacker News 본문이 아니라 FeedBurner의 공식 RSS 주소를 목록 수집의 출발점으로 사용했습니다. 기존 네트워크 코드는 robots.txt를 읽지 못한 경우에도 실제 수집 금지와 같은 오류 문구를 표시했습니다. 따라서 기존 메시지만으로 해당 매체가 모든 수집을 금지한다고 판단할 수 없습니다. 다른 서비스가 사용하는 RSS 주소·캐시·접근 경로까지 확인한 것은 아닙니다.

수정 후 접근 순서입니다. 각 경로의 robots 정책과 허용 도메인을 확인하며, 브라우저 위장이나 차단 우회는 하지 않습니다.

사이트맵·홈페이지에는 기사 본문이 없을 수 있으므로 본문을 별도로 가져옵니다. 제목만 확보되고 본문을 읽지 못하면 추측해서 요약하지 않고 보류합니다. 모든 경로가 실패하면 오류로 남습니다. 성공한 경로와 앞선 실패 원인을 Actions 로그·보고서 수집 상태에 함께 남깁니다.

robots.txt 확인 실패: ... HTTP 403과 robots.txt 규칙에 따른 수집 금지: ...를 이제 구분합니다. robots 확인에 실패한 동일 경로를 강제로 수집하지 않습니다.

보안뉴스 — 현행 기사 주소 형식으로 변경

기존 view.asp?idx= 선택자를 현행 articleView.html?idxno= 선택자로 교체했습니다. 목록도 새 기사 목록으로 변경했으며 목록에서 링크를 찾지 못하면 공식 홈페이지를 시도합니다. 본문 선택자와 발행 시각 추출도 보완했습니다.

기존 목록: https://www.boannews.com/media/t_list.asp
새 목록:  https://www.boannews.com/news/articleList.html?view_type=sm
새 기사:  /news/articleView.html?idxno=...

진행 로그와 BeautifulSoup 경고

수집원·대체 경로·CVE 페이지·요약 배치·HOT 단계를 실행 중에 출력합니다. 워크플로는 python -u로 출력 버퍼링을 줄입니다. 일반 문자열이나 URL을 HTML로 파싱해서 발생하던 MarkupResemblesLocatorWarning은 입력 형태를 구분해 방지합니다. 경고를 전역 숨김 처리하지 않았습니다.

2. 당일 CVE는 무엇을 기준으로 하나요?

NVD API의 published를 한국시간으로 변환한 날짜를 기준으로 합니다. 해당 보고서의 한국시간 00:00부터 수집 시각까지의 CVE를 보여줍니다. CVE ID에 적힌 연도, 예약일, 발견일, lastModified를 공개일로 취급하지 않습니다.

예를 들어 한국시간 9월 22일 13:00 실행이라면, 오늘의 범위는 9월 22일 00:00~13:00입니다. UTC로는 9월 21일 15:00~9월 22일 04:00입니다.

이것은 NVD에 공개된 날짜 기준이며, CVE Program의 최초 공개 시각과 일치한다고 보장하지 않습니다. NVD 반영 지연으로 아직 조회되지 않는 CVE가 있을 수 있습니다. ‘오늘 전 세계에서 공개된 CVE를 빠짐없이 실시간 수집했다’는 뜻이 아닙니다.

하루 3번 실행 때마다 보관 중인 최근 5일 범위를 다시 조회합니다. CVE ID로 중복을 제거하고 해당 공개일의 같은 HTML에 갱신합니다. 19시 이후 등록된 전날 CVE도 다음 실행에서 전날 보고서에 보완합니다. 과거 CVE의 점수가 수정되더라도 이를 오늘의 신규 CVE로 옮기지 않습니다. REJECTED로 바뀐 항목은 조회됐을 때 제거합니다.

NVD가 실패하거나 일부 페이지만 조회된 경우 기존 데이터를 지우지 않고 실패·부분 완료·마지막 정상 조회 시각을 표시합니다. 데이터가 실제로 0건인 경우와 수집 실패를 구분합니다. 보관 기간이 지난 보고서는 기존과 같이 제거합니다.

3. CVE 카드에 표시되는 내용

항목 처리
CVE ID NVD 원본 식별자, NVD 상세 페이지 링크
CVSS 기본 점수, 버전, 등급, 점수 제공기관
간략 설명 NVD 설명을 Gemini가 한국어 1~2문장으로 요약
점수 없음 점수 미제공 — 0점이나 낮은 위험으로 해석하지 않음
다른 평가 펼치면 다른 제공기관·버전의 점수와 벡터 표시
시각 NVD 공개·정보 수정·수집 확인 시각을 한국시간으로 표시

Gemini가 CVSS 점수를 만들거나 계산하지 않습니다. NVD API가 제공한 수치만 표시합니다. 대표 점수는 v4.0 → v3.1 → v3.0 → v2.0 순서로 선택합니다. 같은 버전에서는 Primary를 우선하고 같은 유형이면 NVD를 우선합니다. 다른 점수를 버리지는 않으며 세부정보에서 함께 보여줍니다. 버전이 다른 CVSS 점수는 단순 비교에 한계가 있고 CVSS는 실제 악용 여부를 나타내는 값이 아닙니다.

카드는 대표 점수 내림차순으로 표시하며 점수 미제공 항목은 뒤에 나옵니다. 처음 20건을 표시하고 ‘다음 CVE 보기’로 더 볼 수 있습니다. 검색은 접힌 항목까지 전체를 대상으로 합니다. JavaScript가 꺼져 있어도 HTML에 CVE가 포함되어 있으며 전체를 읽을 수 있도록 설계했습니다.

CVE는 별도 탭입니다. 기존 HOT 10 선정 대상인 뉴스·논문·GitHub 후보 목록은 바꾸지 않았습니다. CVE 카드 자체를 HOT 후보에 자동으로 섞지는 않습니다.

4. 비용과 한국어 요약 대기

NVD 데이터 수집과 Gemini 번역은 별도입니다. CVE 원본 수집 성공 여부와 번역 성공 여부도 구분합니다.

{
  "cve_enabled": true,
  "nvd_timeout_seconds": 35,
  "nvd_interval_seconds": 6.2,
  "nvd_max_pages_per_run": 20,
  "cve_summary_batch_size": 12,
  "cve_summary_max_calls_per_run": 12
}

기본 CVE 요약 배치는 12건입니다. CVE 전용 요청 상한은 실행당 12회이며 재시도를 포함합니다. 요청 하나가 최대 3번 시도될 수 있어 시작 전에 그 여유분을 확보하므로, 모든 호출이 성공해도 12개 배치를 꼭 처리한다는 뜻은 아닙니다. 뉴스·HOT·CVE는 기존 실행당 전체 Gemini 80회 상한을 공유합니다. 전체 한도가 낮으면 실제 CVE 요약 횟수도 줄어듭니다.

수집된 CVE 자체는 번역 호출 한도 때문에 버리지 않습니다. 번역하지 못한 항목은 한국어 요약 대기 + NVD 원문 설명 + 원본 점수를 표시합니다. 다음 실행에서 다시 시도하며 오늘 날짜를 먼저 처리합니다. 설명이 같은 CVE는 기존 번역을 재사용하고 점수만 바뀐 경우 번역을 다시 하지 않습니다.

최초 실행은 최근 5일 CVE를 가져오므로 이전 버전보다 오래 걸리고 Gemini 사용량이 늘 수 있습니다. cve_summary_max_calls_per_run을 높일 때는 전체 max_api_calls_per_run, Gemini 프로젝트 할당량과 청구 내역을 함께 확인하세요. 이 설정은 금액 자체를 보장하는 예산 제한이 아닙니다.

NVD는 페이지당 최대 2,000건을 순회합니다. 안전 상한에 도달하거나 응답이 잘못된 경우 일부 수집 상태를 숨기지 않습니다. 기본 설정의 안전 상한을 넘는 날에는 누락 경고가 남을 수 있습니다.

5. 기존 저장소에 적용하기

업데이트 ZIP을 사용하는 경우

  1. ai-security-digest-v2-update.zip을 PC에서 압축 해제합니다. ZIP 파일 자체를 저장소에 올리는 것이 아닙니다.
  2. GitHub에서 기존 뉴스 프로젝트 저장소의 main 또는 실제 기본 브랜치를 엽니다. news-state 브랜치가 아닙니다.
  3. Add file → Upload files로 압축 해제한 내용물을 저장소 최상위에 올립니다. .github, assets, config, digest, templates, tests 폴더 구조를 그대로 유지하고 같은 경로의 파일은 교체합니다.
  4. 기존에 config/settings.json을 직접 바꿨다면 먼저 백업하고 위 CVE 설정을 병합하세요. config/sources.json을 직접 바꿨다면 기존 추가 수집원을 보존하면서 boannews와 hackernews 항목의 변경사항을 반영하세요. 모델 Variables로 설정한 값은 그대로 사용할 수 있습니다.
  5. Commit changes로 기본 브랜치에 반영합니다. 파일 경로가 .github/workflows/update-news.yml과 digest/cves.py로 보이는지 확인합니다. 폴더 한 겹 안쪽에 넣으면 안 됩니다.
  6. Actions → Update news & deploy → Run workflow를 누릅니다. 최신 기본 브랜치, mode: collect를 선택해 실행합니다.
  7. build·deploy 완료 후 보고서의 CVE 탭, 수집원별 상태, Actions의 단계별 로그를 확인합니다.

예전 실패 실행의 Re-run jobs가 아니라 새 커밋에서 Run workflow를 실행하세요. rebuild는 기존 상태로 HTML만 만들므로 새 CVE나 대체 경로 수집을 확인할 때는 collect가 필요합니다.

.github 업로드가 웹에서 누락되는 경우 Git 방식으로 적용하세요. 저장소를 clone한 로컬 폴더에 업데이트 파일을 같은 경로로 복사한 뒤 다음을 실행합니다. 강제 푸시는 필요 없습니다.

git add .
git commit -m "Fix publisher routes and add daily CVE digest"
git push

news-state 브랜치와 기존 Secret을 삭제하지 마세요. 업데이트 ZIP에는 실행 중 생성된 상태 파일이나 실제 뉴스·CVE 보고서가 포함되어 있지 않습니다. 기존 데이터는 복구·병합되며 상태 버전 1과 호환됩니다.

전체 ZIP을 사용하는 경우

ai-security-digest-v2.zip은 초기 설정용 전체 프로젝트입니다. 압축 내부 ai-security-digest 폴더의 내용물을 저장소 최상위에 배치합니다. 이미 설치한 저장소에서는 업데이트 ZIP만으로 충분합니다. 두 ZIP을 모두 올릴 필요는 없습니다.

6. NVD API 키는 필수인가요?

필수가 아닙니다. NVD API는 키 없이도 요청할 수 있습니다. 공식 안내상 키가 없으면 30초당 5회, 키가 있으면 30초당 50회 요청 제한이 적용됩니다. 이 프로젝트는 키가 있어도 요청 간격을 최소 6.2초로 유지합니다. 같은 외부 IP의 요청이나 서비스 상태에 따라 403·429 등이 발생할 수 있으며 성공을 보장하지는 않습니다.

키를 등록하는 경우:

  1. NVD API 키 신청 페이지에서 이메일과 필요한 항목을 입력하고 약관에 동의합니다.
  2. NVD에서 온 이메일의 활성화 링크를 열어 키를 활성화하고 값을 안전하게 보관합니다.
  3. GitHub의 해당 저장소 Settings → Secrets and variables → Actions → Secrets → New repository secret으로 이동합니다.
  4. Name은 NVD_API_KEY, Secret은 실제 키로 입력합니다.
  5. 저장 후 최신 기본 브랜치에서 collect를 실행합니다.

키를 코드나 settings.json에 쓰지 않습니다. 기존 GEMINI_API_KEY와 다른 키이며, Gemini 키는 그대로 둡니다. 워크플로에는 NVD Secret 참조가 추가되어 있습니다.

7. 검증 범위

검증한 항목: Python 단위·통합 테스트 91개 통과. 날짜 경계, 페이지 순회, 누락·실패 표시, CVSS 원본 보존, 캐시, 거절된 CVE 제거, 기존 상태 호환, 수집 대체 경로, HTML 이스케이프 등을 확인했습니다. JavaScript 구문 검사와 빈 상태에서의 HTML 생성도 통과했습니다.

Headless Chromium의 12개 화면 크기에서 목록·보고서 24개 배치 검사와 CVE 열 수·가로 넘침 검사, CVE 더 보기·전체 검색·세부정보 펼치기를 확인했습니다. 실제 뉴스가 아닌 명시적으로 표시한 테스트 데이터를 사용했습니다.

검증하지 못한 항목: 컨테이너 환경의 외부 DNS와 localhost 브라우저 탐색이 제한되어 실제 사이트의 원본 HTTP 수집, NVD API 실호출, Gemini 실호출, 사용자 GitHub Actions·Pages 실행은 확인하지 못했습니다. 화면 시험은 HTML을 메모리에 주입했고 브라우저 저장소는 모의 객체를 사용했습니다. 실제 HTTP 탐색·CSP·스토리지 영속성·JavaScript 비활성 브라우저·폴드 실기기 시험을 통과했다고 주장하지 않습니다.

웹 조회에서는 보안뉴스의 현행 기사 목록·주소 형식과 The Hacker News의 공개 경로, NVD 공식 API 문서를 확인했습니다. 이것은 수정한 Python 코드가 실제 GitHub 러너에서 모든 경로를 성공적으로 수집했다는 의미가 아닙니다. 수집원 HTML, 접근 정책, 네트워크 상황은 다시 바뀔 수 있으므로 첫 실행의 새 로그를 기준으로 확인하세요.
